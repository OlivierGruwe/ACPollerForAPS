Concepts

ACPollerForAPS converts invoices exported from APS (ReadSoft) into the format each destination ERP expects, and delivers them where the ERP imports them. Single input format (APS XML), multiple outputs depending on the Buyer.

Pipeline (per scheduled run): scan the input folder → route each file to a channel by Buyer → merge files of the same channel → convert (CSV/XML via the provider) → deliver (FS/FTPS/S3) → archive sources only if delivery succeeded.

The service and the UI share a single settings.json ({ "Pipeline": { ... } }). The service reads it at startup.

After a change through the UI, restart the service so it picks up the new configuration.

Preview

Load a Sample XML in the channel, then click Preview to see the generated output. Refresh paths re-scans the sample XML. Validate (toolbar) checks the whole config.

Output transports

Each channel delivers via a transport, with configurable retry. On failure after all attempts, sources are not archived and are retried next run.

ERP Providers (plugins)

Hybrid model. Default "mapping" covers most ERPs with no DLL. For specific logic, ship a DLL implementing IErpExporter in the providers/ folder next to the service exe; set the channel Provider to its name. The service discovers it at startup (a broken DLL is logged and ignored).

public interface IErpExporter
{
    IEnumerable<string> ProviderNames { get; }
    ExportResult Export(IEnumerable<string> inputXmls, OutputChannel channel);
}

Steps: new class library (.NET 4.8) referencing ACPollerForAPS.Core → implement IErpExporter → fill result.Content → compile → drop the DLL in providers/ → set Provider to its name. No service recompilation. See PROVIDERS.md for the full guide.

Operations

Logs

NLog writes to logs/ next to the service exe, with daily + size rotation and purge. Each run logs a start line, per-file detail and a summary. Set the level to Debug in NLog.config for diagnostics, then back to Info.

Monitoring (Windows Event Log)

The service reports to a dedicated Windows event log ACPollerForAPS (Event Viewer → Applications and Services Logs). Business events (start/stop, per-run summary) plus all warnings/errors, graded by severity. Any enterprise monitor (Nagios, Zabbix, Centreon) reads it natively.

IDSeverityMeaning
1000 / 1001InformationService started / stopped
1100InformationRun completed OK (summary)

PowerShell: Get-EventLog -LogName ACPollerForAPS -Newest 20. The event source is created at service installation (admin). Reinstall the service to create it.

Service lifecycle

sc start ACPollerForAPS
sc stop  ACPollerForAPS

Restart the service after changing settings.json.
